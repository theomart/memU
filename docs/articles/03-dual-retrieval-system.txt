🎯 RAG is fast but dumb. LLM ranking is smart but slow. Why not both?

User asks: "What did she say about the deadline?"

RAG approach: embed query, search vectors, return top 5 chunks mentioning "deadline" or "she".

Problem: who is "she"? The system has no idea. Returns random deadline mentions.

LLM approach: look at conversation history, understand "she" = Sarah from the previous message, search for "Sarah" + "deadline", rank results by relevance.

Problem: takes 3 seconds instead of 50ms.

Solution: build both, let the query decide.

👞 Non technical TLDR

Simple queries use RAG:
- "What's the user's email?" → vector search → 50ms
- "When is the meeting?" → vector search → 50ms

Complex queries use LLM:
- "What did she say about that?" → needs context resolution → 2s
- "Summarize our project discussions" → needs semantic ranking → 3s

The system can auto-detect which to use based on query complexity.

🔬 Technical TLDR

RAG path:
Query: "user's favorite color"
→ Embed query
→ Cosine similarity against memory embeddings
→ Top 5 results: ["User mentioned liking blue", "User bought a blue car", ...]
→ 50ms total

LLM path:
Query: "What did she recommend for the API issue?"
→ LLM resolves "she" to "Sarah" using conversation history
→ Rewritten query: "What did Sarah recommend for the API authentication issue?"
→ Search with rewritten query
→ LLM ranks results by relevance to the actual question
→ 2-3s total

🥊 The sufficiency check

This is where it gets interesting. After searching each layer, ask: "Do we have enough?"

Query: "What's the user's job?"
→ Search category summaries
→ Found: "Work: User is a senior engineer at Stripe, joined in 2022"
→ Sufficiency check: YES
→ Stop. Don't search 10,000 individual memories.

Query: "What exactly did the user say about the authentication bug?"
→ Search category summaries
→ Found: "Technical issues: User encountered auth bugs"
→ Sufficiency check: NO, need specifics
→ Search memory items
→ Found: "User said OAuth token refresh was failing silently on March 3"
→ Sufficiency check: YES
→ Stop. Don't search raw conversations.

Query: "Show me the full conversation about the auth bug"
→ Goes all the way to Layer 1 (raw resources)

⏳ Real latency numbers

RAG, 10k memories:
- Category search: 10ms
- Item search: 30ms
- Resource search: 50ms
- Worst case: 100ms

LLM ranking, 10k memories:
- Category ranking: 1s
- Item ranking: 2s
- Resource ranking: 3s
- Worst case: 6s

But with sufficiency checking, 70% of queries stop at category level.

🛠 Pre-retrieval decision

Before any search, ask: does this query even need memory?

"Hello!" → No retrieval needed
"What's 2+2?" → No retrieval needed
"What did I tell you about my project?" → Retrieval needed

This saves ~30% of retrieval calls. The LLM learns to recognize greetings, general knowledge questions, and meta-questions about the system itself.
