🧠 How do you make an AI agent actually REMEMBER things?

Most agents dump everything into a vector database. User says "I love Italian food" in January, mentions "my daughter's birthday is in March" in February, asks "what should I cook?" in April.

The agent searches, gets 50 random chunks, and responds with generic pasta recipes. No mention of the daughter. No connection between the memories.

Here's a better approach: 3-layer hierarchical memory.

👞 Non technical TLDR

Layer 1 stores raw conversations. The actual chat logs.

Layer 2 extracts atomic facts: "User loves Italian food", "User has a daughter", "Daughter's birthday is in March".

Layer 3 groups these into categories with summaries: "Family: User has a daughter, birthday in March. Food preferences: loves Italian, especially pasta."

Now when the user asks "what should I cook?", you check Layer 3 first. You see it's March. You see daughter's birthday. You see Italian preference. Response: "How about making fresh pasta for your daughter's birthday this month?"

🔬 Technical TLDR

Layer 1 - Resources:
- Raw conversation: "My daughter turns 8 in March, we usually do a family dinner"
- Stored with: URL, timestamp, embedding vector

Layer 2 - Memory Items:
- Extracted: "User has daughter", "Daughter turns 8", "Birthday in March", "Family dinner tradition"
- Each tagged: profile, event, knowledge, behavior, or skill
- Each has its own embedding

Layer 3 - Memory Categories:
- "Family" category summary: "User has a daughter turning 8 in March. They do family dinners for birthdays."
- "Traditions" category summary: "Birthday celebrations involve family dinners."

The magic is the many-to-many linking. "Daughter's birthday dinner" connects to Family, Traditions, AND Food Preferences categories.

🥊 Why not just vector search?

Vector search on "what should I cook": you get chunks about cooking, food, maybe kitchen stuff.

Hierarchical search: Category summaries surface "March = daughter's birthday + Italian food preference". Then you drill down to specific items if needed.

Query: "what should I cook?"
→ Check categories → "Food Preferences" + "Family" both relevant
→ Category summaries mention: Italian food, daughter's birthday in March, family dinner tradition
→ Stop here. Enough context. No need to search 10,000 memory items.

🍓 The traceability win

Every summary traces back to facts, which trace back to original conversations.

"User loves Italian food" → extracted from conversation on Jan 15 → original message: "I could eat pasta every day, it's my favorite"

No hallucinated memories. Full audit trail.
