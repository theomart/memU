🍄 How do you teach an LLM to extract memories WITHOUT hallucinating fake ones?

User says: "I've been coding in Python for 5 years, mostly Django. Last week I started learning Rust because my manager suggested it."

Bad extraction: "User is an expert Python developer who loves Django and is mass excited about Rust."

Good extraction:
- profile: "5 years Python experience"
- profile: "Works with Django"
- event: "Started learning Rust last week"
- event: "Manager suggested learning Rust"
- skill: "Python proficiency (5 years)"

The difference? Structured memory types + strict extraction rules.

👞 Non technical TLDR

5 memory types, each with a specialized extractor:

profile → "User is 32 years old", "Works as a PM at a fintech startup"
event → "Attended PyCon last month", "Got promoted in January"
knowledge → "Knows that PostgreSQL supports JSON columns"
behavior → "Usually codes in the morning", "Prefers dark mode"
skill → "Fluent in Spanish", "Can write production Python"

Each type has its own prompt. The profile extractor looks for stable traits. The event extractor looks for time-bound experiences. No mixing.

🔬 Technical TLDR

The prompt structure that works:

1. Task: "Extract profile memories from this conversation"
2. Definition: "Profile memories are stable characteristics, demographics, preferences that don't change frequently"
3. Rules: "Extract ONLY explicit statements. Do NOT infer. Do NOT extrapolate."
4. Format: XML output with type attribute
5. Examples:

Input: "I moved to Berlin 3 years ago for work"
Output:
<memory_items>
  <item type="profile">Lives in Berlin</item>
  <item type="profile">Relocated for work</item>
  <item type="event">Moved to Berlin 3 years ago</item>
</memory_items>

6. Edge cases: "If timing is mentioned, also create an event memory"
7. Quality check: "Each item must be independently understandable"

Why XML over JSON? LLMs hallucinate JSON structure less with XML. Closing tags are easier to validate.

⚡ The parallel extraction trick

Don't run 5 extractors sequentially. Run them in parallel.

Conversation → 5 parallel LLM calls (profile, event, knowledge, behavior, skill) → merge results → dedupe

Total latency: ~1 LLM call, not 5x.

🍓 The critical instruction

"Extract ONLY what is explicitly stated. Do NOT infer, assume, or extrapolate."

User says: "I work at Google"
Good: "Works at Google"
Bad: "High income", "Lives in Bay Area", "Has good benefits"

The bad ones might be true, but they're inferences. Inferences become hallucinations at scale.
