🦎 AI memory storage cheat sheet for practical deployments.

Here are 3 backend options for your agent memory: InMemory, SQLite, PostgreSQL. When to use each.

---

👞 Non technical TLDR

- Development? Use InMemory (zero setup, data disappears on restart)
- Single user app? Use SQLite (one file, portable, good enough)
- Production? Use PostgreSQL + pgvector (scales, native vector search = go brrrr)

---

🔬 Technical TLDR

- All backends should implement the same Database protocol → swap with one config change
- Protocol-based design = duck typing, no inheritance, easy mocking for tests

---

📊 Backend comparison

InMemory:
- Persistence: none
- Setup: zero
- Vector search: NumPy cosine
- 10k vector search: ~50ms
- Concurrency: single process

SQLite:
- Persistence: file
- Setup: DSN string
- Vector search: brute-force
- 10k vector search: ~100ms
- Concurrency: single writer

PostgreSQL:
- Persistence: server
- Setup: full server
- Vector search: pgvector HNSW
- 10k vector search: ~5ms
- Concurrency: full ACID

---

⚡ pgvector is the real upgrade

Without pgvector:
- Store embeddings as JSON arrays
- Brute-force cosine similarity in Python
- O(n) for every search

With pgvector:
- Native vector(1536) column type
- HNSW approximate nearest neighbor index
- O(log n) search, SIMD acceleration

To put that in perspective: 10k vectors goes from ~100ms to ~5ms. At 1M vectors, it's the difference between "works" and "unusable".

---

🛠 Configuration examples

Development:

store = InMemoryStore()

Lightweight deployment:

store = SQLiteStore(
    dsn="sqlite:///./data/memory.sqlite"
)

Production:

store = PostgresStore(
    dsn="postgresql://user:pass@db:5432/memory",
    vector_provider="pgvector",
    ddl_mode="create"
)

---

👨‍🍳 Recipe for multi-tenant setup

Use scope models for tenant isolation:

class MyScope(BaseModel):
    user_id: str
    org_id: str | None = None

store = PostgresStore(
    dsn="...",
    scope_model=MyScope
)

items = store.memory_item_repo.list_items(
    where={"user_id": "user_123"}
)

No manual tenant filtering. No data leaks. Clean.

---

🍓 Key insight

A clean Database protocol means you can start with InMemory for prototyping, graduate to SQLite for MVP, then PostgreSQL for scale - WITHOUT changing application code.

Swap the store, keep the logic.
